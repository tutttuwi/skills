# 作成前の確認

新規デッキでは、依頼・添付素材・既存の設定から回答済みの項目を拾う。未確定の項目は推奨案を添えて一度に聞き、回答を待ってから本文作成とレンダリングへ進む。編集依頼では、既存デッキで確認済みの設定を引き継ぎ、変更の対象や意図に関わる不明点を確認する。

| 確認項目 | 確認する内容 |
| --- | --- |
| 資料の目的と読者 | 誰に何を理解・判断・実行してほしいか。目的の分類は [目的一覧](selection.md) から選ぶ |
| 用途別プリセット | 決算・業績説明、製品・サービス発表、技術解説・社内共有、自由構成 |
| ブランド | コバルト、ティール、プラム、またはユーザー提供のブランド。既存ブランドなら色、書体、ロゴの指定を確認 |
| 表示モードとコントラスト | ライト／ダーク、標準／高コントラスト |
| 発表・配布の条件 | 発表用か配布用かで密度が大きく変わる場合は確認。枚数、言語、形式、素材の指定も反映する |

質問の例

> 新人エンジニアが再試行の可否を判断できる資料として、技術解説プリセット・コバルト・ライト・高コントラストを提案します。こちらで進めてよいですか？ 変更したい場合は、目的・プリセット・ブランド・モードのうち該当する項目だけ教えてください。

すでに読者・目的・プリセット・ブランド・モード・コントラストが指定されていれば、採用する内容を短く伝え、そのまま進める。既存設定の使用や候補の選択を任された場合は、その範囲の選択を伝える。ブランドガイドの提供を希望している場合は、必要な素材が届いてから反映する。

## 資料プリセット

| ID | 用途 | ページの展開 |
| --- | --- | --- |
| [earnings](presets/earnings.yaml) | 決算・業績説明 | 主要指標 → 増減要因 → セグメント → 見通し → 参照資料 |
| [product-launch](presets/product-launch.yaml) | 製品・サービス発表 | 提供価値 → 利用場面 → デモ → 根拠 → 次の行動 |
| [technical-brief](presets/technical-brief.yaml) | 技術解説・社内共有 | 結論 → 状況 → 判断 → 実装 → 確認 |
| [flexible](presets/flexible.yaml) | 自由構成 | 選んだ目的の展開を起点に、読者と資料に合わせる |

ページ数は依頼を優先する。短い資料では近い役割を統合し、長い資料では比較対象や章ごとに展開する。各ページの主役を、見出し・KPI・図・実画面・比較のいずれかに絞り、表やカードが続く場合は内容に合う別の表現を検討する。

## ブランド設定

| ID | 配色 | 合わせやすい用途 |
| --- | --- | --- |
| [cobalt](brands/cobalt.yaml) | コバルト × アンバー | 技術解説、社内レビュー、決算 |
| [teal](brands/teal.yaml) | ティール × バイオレット | 製品説明、プロセス、業績 |
| [plum](brands/plum.yaml) | プラム × ピンク | 製品発表、キーノート |

- ライトは明るい面に濃い文字、ダークは暗い面に明るい文字を置く。モードの選択はPDF・PNGにも反映される。ブランドの既定骨格は `modern`。別の登録テーマを指定した場合はタイポグラフィや形状などに反映する。
- `standard` では本文・補足・アクセント文字と主要3背景のコントラスト比を4.5:1以上、`high` では7:1以上にする。数字や警告はラベルも併用し、外部素材やチャートはレンダリング後に確認する。 [W3C WCAG 2.2 Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 独自配色は、任意のブランドYAMLを同じ形式で用意し、`brand: { file: ./brand.yaml }` で指定する。パスは `presentation.yaml` からの相対パス。書体・ロゴの指定はデッキのCSSと素材へ反映する。

## スライドへの反映

`resolve.ts --frontmatter` が選択したブランドのCSSをMarkdownの先頭に展開する。タイトルやページ固有のCSSを追加する場合は、展開された共通スタイルの後に必要なルールを足す。配色やモードを変更したら、フロントマターを更新する。

- 表紙や章の導入は `<!-- _class: "brand-cover" -->`。同じブランドの色で余白の多いページを作る。
- 説明枠は `<article class="card accent-card">`。補助のカードは `secondary` を加える。色を使う領域は端の線、ラベル、必要な強調に絞り、本文は本文色を使う。
- KPIの数値には `brand-kpi`、判断や次の行動を短く示す帯には `brand-focus`。出典と比較の条件は通常の文字で読めるようにする。
- 外部の写真・SVG・グラフを使うときはライト／ダーク向けの線・文字・背景を合わせ、状態の違いはラベルや線種でも示す。
