# ナレッジファイルの形式

## 置き場所とファイル名

```text
<登録先>/knowledge/yyyy-mm-dd_<概要>.md
```

- `yyyy-mm-dd` は登録する日 (今日)。
- `<概要>` は内容が一目で分かる短い名前 (日本語可、目安は 40 文字以内)。
  - 空白は `-` に置き換える。
  - ファイル名に使えない文字 (`/ \ : * ? " < > |`) と、Obsidian のリンクを壊す `[ ] # ^` は使わない。
- 同じ名前が既にあれば、末尾に `-2` を付ける。
- 例: `2026-11-20_gh-pr-createで-head-ブランチを指定する.md`

## 本文のテンプレート

````markdown
---
title: <タイトル>
date: yyyy-mm-dd
tags: [tag1, tag2]
source: <任意。どのツール・どの作業で得た学びか>
---

# <タイトル>

## 要約

一〜三行で、何が分かったか。結論から書く。

## 背景

どういう状況・目的で起きたか。読み手がこの文脈を知らなくても分かるように。

## 学び

原因、解決策、判断理由。手順やコマンドは再現できる形で書く。

```bash
実際に動いたコマンドや設定
```

## 参考

- 公式ドキュメントや Issue の URL (あれば)

## 関連

- [[2026-10-03_関連するナレッジ]] — 関連する理由を一言
````

- `背景` と `参考` は書くことがなければ節ごと省く。`要約` と `学び` は必ず書く。
- `tags` は小文字の kebab-case を基本にする。新しく作る前に、既存ナレッジで使われているタグを調べて、同じ意味なら揃える。
- 会話のやり取り (「ユーザー: ... / AI: ...」) をそのまま写さない。後から読む人にとって必要な事実と結論に整理する。
- 秘密情報は伏せ字にするのではなく、最初から書かない。

## Obsidian リンク

- 書式は `[[ファイル名]]`。拡張子 `.md` と `knowledge/` のパスは付けない。Obsidian はファイル名でリンクを解決する。
  - 良い例: `[[2026-10-03_dockerのビルドキャッシュ]]`
  - 見出しへ飛ばしたいときは `[[ファイル名#見出し]]`。
- 表示名を変えたいときは `[[ファイル名|表示名]]`。ただし `|` は Markdown の表の中で崩れるので、表の外で使う。
- リンクするのは、実在するファイルだけ。ファイル名を記憶や推測で書かず、一覧から確かめて写す。
- 関連の理由を一言添える。理由が書けないものは関連ではないので外す。
- 関連が見つからなければ `## 関連` の節ごと省く。無理に結ばない。
- 目安は多くても五件。多いと、どれが本当に近いのか分からなくなる。

## 既存ナレッジへの追記

新規ファイルではなく追記を選んだときは、既存ファイルの `学び` の末尾に日付つきの小見出しで足す。

```markdown
### 追記 yyyy-mm-dd

追加で分かったこと。
```

frontmatter の `date` は元の日付のまま残す。
